## Problem Statement

在 `Spec 0009` 完成五池最小相对熵（KL/IPF）闭合校准、精确整数规划 `3+1` 精算配单与 240+ 场真实体彩完场 OOS 科学门禁闭环后，高频真机看盘与体彩店实操暴露出 10 项交互阻塞、空间浪费与认知割裂问题：

1. **说明书搜索劫持章节跳转与边缘状态遗漏**：用户在图文说明书顶部搜索「一球小胜卡盘」等复合词时，章节精确子串过滤返回空集并将当前视图锁死在问答首页，导致点击问答卡片内的「📖 跳转查看该功能完整矢量图解 ›」或顶部章节标签毫无反应且内容区不滚回顶部；同时移动端说明书弹窗漏传问答配额同步回调，安全网关封禁表异步持久化在落盘改名前缺少并发序号二次校验。
2. **真机与桌面端上下留白浪费屏效**：安卓原生伴侣端容器外层系统栏内边距与网页安全区内边距、固定顶底间距以及非展示帧下多余的 `15px` 仿横条层层叠加，桌面端顶栏亦被平铺的 8 皮肤胶囊与双行标题撑高，压缩了首屏可视比赛场数。
3. **精算配单底部双栏重叠与语义打架**：移动端切至「精算配单」时，底部同时悬浮着手动串关胶囊条（场数/过关/倍数/审单）与页面底部的「套用方案并查看审单台」主按钮，不仅在窄屏及安全区下互相遮挡重叠，更造成“手动等倍”与“智能不等倍套用”的操作混淆。
4. **缺少清晰 1-2-3 主流程引导且控件杂乱**：移动端与电脑端（原左选球 → 中审单 → 右配单逆序排布）均缺乏直观的「选球 → 配单 → 审单」向导指示，页面平铺大量低频/重复按钮（如首屏教学演示胶囊、双单关按钮、重置2场、沙盒重复倍数器、四处刷屏的超感与皮肤按钮），且用户在赛事雷达选好球队后切往精算配单仍需额外手动点一次同步才生效。
5. **全赛果组合盈亏推演明细被省略号截断**：多场串关或容错方案下，组合明细行强制单行省略截断（`...`），用户无法看清每一组赛果具体命中了哪几场比赛的什么选项与水位，也看不出该场景具体由哪几张物理实票派奖构成。
6. **投倍与配单预算档位脱离实战高频习惯**：数字键盘快捷倍数仍为 `[1, 5, 10, 20, 50, 99]`（50 倍、99 倍极少点选，反而缺高频的 2/3/4 倍），精算配单预算最低锁在 `¥50`（内核锁 `¥20`）且不支持自定义金额输入，无法覆盖日常 `¥10 / ¥20` 轻仓实操。
7. **「看球直觉倾向」变化隐晦不可感知**：在开启雷达选队同步锚定或最优票面未变时，切换「纯客观 / 偏主队 / 防爆冷」仅在底层微调几个百分点的真赚钱率与期望回报率，界面既无实时作用说明，也无相对纯客观基准的 `Δ` 差值反馈，用户误以为按钮失效。
8. **「套用方案 → 审单锁利」跨页切换零感知**：点击套用方案切往审单页时，目标容器在手机端尚未挂载即提前触发扫光动效导致落空，瞬间生硬切页让用户视线无法确认已进入对应方案的审单状态。
9. **情报账本单薄且「联合会诊」与「精算配单」自我打脸**：前端丢弃了服务端已返回的逐场精算点评与消息消化度明细，缺少赛前盘面微观信号展开流；更严重的是，「扫地僧小高」多场联合会诊未读取当前注单是否已完成精算配单分倍、零假中奖配平或旋转矩阵缩水，一律按散户裸买死串泼冷水批评，造成前后体验严重割裂。
10. **专业精算信息密度与清爽首屏难以兼顾**：五维透视舱、精算推导依据、全赛果矩阵与深度情报全部平铺展开，首屏视觉压迫感强，亟需建立「外简内丰」的三维翻转卡片与物理弹簧折叠抽屉体系。

## Solution

在 **100% 严守精算数学内核红线**（除将预算入参下限由 `¥20` 放宽至 `¥10` 外，严禁改动五池最小相对熵校准、经验贝叶斯收缩、精确 0-1 背包、线性/整数规划、旋转矩阵与错价雷达纯正期望硬门禁，保持四层科学基准 100% 全绿）及商业保密红线的前提下，实施十大体验与协同升级：

1. **修复图文说明书分词检索、任意态无阻断章节跳转置顶高亮、移动端配额同步与封禁持久化并发序号守卫**。
2. **双端与安卓伴侣端极致紧凑屏效**：消除非展示帧下的多余底部假横条与安全区双倍留白，将全站散落的 8 套皮肤、超感震动与 8 皮肤墙统一归口至顶栏「🎨 外观与触感」弹出抽屉，最大化首屏比赛可视面积。
3. **构建「① 赛事雷达选球 → ② 精算配单 → ③ 审单锁利」三步精算向导与单主按钮（Primary CTA）体系**：
   - 电脑端三栏顺次重排为「左栏 ① 选球定方向 → 中栏 ② 3+1 精算配单 → 右栏 ③ 五维审单锁利（可切换情报账本）」；
   - 移动端顶栏内嵌紧凑可点按的 `① → ② → ③` 步骤指示条，在「精算配单」与「情报账本」彻底收起手动串关悬浮条以根除重叠打架，并在赛事雷达已选球时默认自动开启雷达选队同步锚定。
4. **全盘清理 6 类鸡肋与重复入口**，将投倍快捷档升级为 **`1 / 2 / 3 / 4 / 5 / 10 倍`**，将精算配单预算升级为 **`¥10 / ¥20 / ¥50 / ¥100 + 自定义偶数金额（¥10 ~ ¥20,000）`** 并对 `¥10`（5 注）多场数学边界做诚实最小本金引导。
5. **透明化「看球直觉倾向」**：展示一句话实时作用说明、「点选即实时重算」提示、雷达锚定方向锁定说明，以及相对纯客观基准的 `Δ 真赚钱率`、`Δ 期望 EV%` 与票面变动微标。
6. **打造仪式感「方案移交 → 审单锁利」跨页过渡动效**：挂载后自动滚回审单顶部、展开带脉冲扫光的方案交接确认横幅（`✅ 当前正在审阅：精算配单【XX】¥Y 方案`）并推进步骤条。
7. **重做无省略号「全赛果组合盈亏推演明细」**：以自动换行分场赛果徽章完整呈现每场命中项与水位，配备红绿净盈亏比例条、`亏损/回血优先 | 高概率优先 | 高盈利优先` 三态排序，以及点击展开该场景命中的逐张物理实票构成。
8. **升级深度盘面情报流与「双维协同会诊」**：零配额实时生成每场比赛可展开的五池微观盘面拆解（水位升降、`xG`、节奏相关性、一球卡盘温度及胜平负/让球/进球三维度影响），并在「扫地僧小高」多场联合会诊中注入只读精算方案结构上下文，输出「🛡️ 已构筑的精算防线 + ⚡ 盘面消化度与残余实战暗雷」双维客观报告。
9. **落地「外简内丰」交互哲学**：核心决策总览大卡（精算配单总览卡、五维真相透视卡）采用双面不透明 **3D 翻转卡片（3D Flip）**，动态高度列表与沙盒面板采用 **物理弹簧折叠抽屉（Spring Collapse Drawer）**，全量适配 8 套触感材质皮肤与 `prefers-reduced-motion` 无障碍降级。

## User Stories

### 一、图文说明书无阻断检索跳转、配额同步与网关持久化防覆盖

1. 作为查阅术语的内部成员，当我在图文说明书顶部搜索框输入「一球小胜卡盘」等复合词时，我希望系统通过分词与模糊匹配同时命中「精算名词词典」与「滑块沙盒&6仪表」等相关章节，以便不再因整串精确匹配落空而被锁死在默认页。
2. 作为向「内部说明书助手」提问后的成员，即使顶部章节搜索框仍有残留文字，当我点击回答下方的「📖 跳转查看该功能完整矢量图解 ›」或手动点击顶部任一章节页签时，我希望界面立即解除搜索词劫持、平滑切换至目标章节、自动将内容区滚回顶部并对目标图解卡片执行醒目聚焦高亮，以便一秒定位图文解释。
3. 作为在手机端向「内部说明书助手」发起长尾场景提问的成员，我希望每次消耗智能配额后，个人账本与账号状态区的「今日智能诊盘额度」立即实时扣减同步（与电脑端完全一致），以便准确掌握剩余配额。
4. 作为平台安全运维者，当 48 小时封禁持久化定时器正在异步写入临时文件期间若封禁序号再次递增，我希望系统在原子改名覆盖前二次核验序号并清理过期临时文件，以便绝不发生旧快照覆盖新封禁状态。

### 二、极致屏效、安全区去重与「🎨 外观与触感」统一归口

5. 作为使用手机浏览器或安卓原生伴侣端看盘的成员，我希望非展示帧真机环境下彻底移除底部多余的 `15px` 仿横条占位，并校准系统栏内边距与网页安全区使顶栏与底栏紧凑贴合、零双倍叠加留白，以便首屏直接多看 1～2 场完整赛事赔率。
6. 作为使用电脑宽屏工作台的成员，我希望顶栏高度紧凑单行化，将原本占满顶栏中部的 8 个皮肤胶囊、超感震动按钮、8 皮肤墙入口及重复的打票单按钮收拢为清爽的「🎨 外观与触感」弹出抽屉（移动端同样移除 4 页顶栏重复刷屏的超感按钮与账本页中间突兀的 8 皮肤大色卡），以便把宝贵屏幕面积全部留给盘口与精算数据。

### 三、「① 选球 → ② 精算配单 → ③ 审单锁利」向导动线与零遮挡底栏

7. 作为初次或高频使用工作台的成员，我希望在手机端顶栏与电脑端顶栏一眼看到可点击跳转的「① 赛事雷达选球 → ② 精算配单 → ③ 审单锁利」三步状态流转条，明确感知当前所处环节与下一步动作，以便告别满屏菜单迷茫感。
8. 作为使用电脑宽屏工作台的成员，我希望三栏从左至右顺应人眼直觉排布为「左栏：① 赛事雷达选球 → 中栏：② 3+1 精算配单 → 右栏：③ 五维审单锁利（可切换情报账本）」，以便顺畅完成从选球、配单到审单锁利的单向视线闭环。
9. 作为在手机端进入 Step ①「赛事雷达」选球的成员，当我勾选至少 1 场比赛后，我希望底部投控栏既支持快速调整过关/倍数，又以唯一醒目的主行动按钮引导「下一步：② 精算配单」（同时支持切往审单），以便顺滑进入精算配平。
10. 作为在手机端进入 Step ②「精算配单」的成员，我希望底部不再悬浮手动串关胶囊条（彻底消除与「套用方案」按钮的重叠遮挡及语义打架），而是将「套用【当前流派】方案 → 进入 ③ 审单锁利」固定在安全区之上的专属无遮挡行动位，以便在任何机型视口下都能清晰一键套用。
11. 作为已在 Step ①「赛事雷达」勾选了心仪球队的成员，当我查看 Step ②「精算配单」时，我希望系统默认自动实时承接并锚定我在雷达所选的比赛与球队方向（无需再手动多点一次同步按钮）；而当我想脱离已选注单做纯盘面客观探索或增减 1～8 场目标对决池时，可随时点开顶部联动折叠条一键切换「纯盘面自由选池」，以便兼顾零冗余操作与自由探索。

### 四、接地气倍数/预算档位、¥10 数学边界诚实引导与鸡肋菜单清理

12. 作为手动调节倍数的成员，我希望点开投倍数字键盘时直接看到最接地气的 **`1倍 / 2倍 / 3倍 / 4倍 / 5倍 / 10倍`** 六格快捷按钮（同时保留九宫格自由输入 `1 ~ 999` 倍），以便高频小倍微调一触即达。
13. 作为轻仓实战或大额定制的成员，我希望在精算配单顶部直接点选 **`10元 / 20元 / 50元 / 100元`** 快捷预算档，或点击 **`⌨️ 自定义`** 输入 `¥10 ~ ¥20,000` 任意金额（自动按 `¥2` 整数注偶数对齐），以便用 10 元、20 元小资金也能享受帕累托精算配单。
14. 作为选择 `¥10`（共 5 注）预算并圈选多场比赛的成员，当 5 注本金在数学硬约束下不足以拆出零假中奖方案（使【① 稳健保本】无可行实票）时，我希望看到专属的**诚实最小保本本金引导卡**（支持一键升至 `¥20 / ¥50` 或切看【② 期望效用】，绝不误报为“无跨盘错价洼地”）；当【③ 容错缩水】旋转矩阵最少张数（如 6 场 6 注 `¥12`）略高于 `¥10` 时，在金额旁清晰注明最低法定整数注成本，以便在不妥协精算严密性的前提下明明白白决策。
15. 作为专注实战看盘的成员，我希望赛事雷达首屏不再出现易误触冲掉真单的 3 个教学演示胶囊（统一移入图文说明书快速上手页），不再出现与顶部分段器重复的第二个「单关」胶囊，对决池不再出现无意义的「重置2场」，审单沙盒内不再出现与底栏完全重复的第二组倍数步进器，以便界面干净利落、零误触干扰。

### 五、「看球直觉倾向」透明感知与跨页方案移交仪式感动效

16. 作为在精算配单切换「看球直觉倾向（`纯客观 / 偏主队 / 防爆冷`）」的成员，我希望紧邻按钮下方实时显示当前档位的一句话精算作用说明及「点选即实时重算下方方案，无需组合其他按钮」提示；若当前处于雷达选队同步锚定状态，温和说明「球队方向已由雷达选单锁定，直觉倾向仅微调概率评估与分倍权重」，以便彻底消除“点了没反应”的困惑。
17. 作为切换至「偏主队」或「防爆冷」的成员，我希望在配单总览指标上直接看到相对「纯客观」基准的实时差值微标（如 `Δ真赚率 +2.4%`、`Δ期望EV +1.8%` 或 `实票分倍已重排`）并伴随数值微动效，以便一眼看穿倾向调节带来的精确边际变化。
18. 作为点击「套用【某某】方案并查看审单台」的成员，我希望无论在手机端切页还是电脑端跨栏聚焦时，都能看到流畅的步骤条推进动画、目标审单容器自动滚至顶部、激光扫光脉冲，以及醒目的方案交接状态横幅 **`✅ 当前正在审阅：精算配单【稳健保本】¥X 方案（共 K 张实票 · 可直接核对打票或微调）`**，以便眼睛 100% 明确感知方案已挂载到位。

### 六、无截断全赛果盈亏推演明细与逐票溯源

19. 作为在审单台核查「全赛果组合盈亏推演明细」的成员，我希望彻底告别 `...` 单行省略号截断，每一种互斥赛果组合均以自动换行的分场小徽章完整展示涉及的每一场比赛、玩法、命中选项与水位，并配有直观的红绿净盈亏比例条、发生概率、单倍奖、实派总额与净盈亏金额，以便多关串关也能把每一场赛果看得一清二楚。
20. 作为重点排查亏钱风险或推演高回报场景的成员，我希望在组合盈亏明细顶部一键切换 **`亏损/回血优先 | 高概率优先 | 高盈利优先`** 三种排序视图，并可点击任意一行赛果组合丝滑展开「该场景命中的具体物理实票清单」（显示命中的是第几张票、多少倍、单注奖金与该张实票贡献的派奖额），以便一秒对清每一分奖金来自哪张彩票。

### 七、深度盘面情报流、双维客观协同会诊与「外简内丰」翻转抽屉

## Implementation Decisions

### 1. 最高优先级精算与保密不变量（零数学退化红线）

- **精算黑盒严禁篡改**：五池分割一致去水、`{0..14}²` 先验最小相对熵（KL/IPF）闭合校准、经验贝叶斯收缩、商状态空间积分器、精确 0-1 背包、对数财富效用、旋转矩阵 $C(v,k,t)$ 线性/整数规划及错价雷达纯正期望硬门禁数学逻辑 **保持 100% 原封不动**。
- **唯一精算入参放宽**：仅将服务端精算配单生成器与工作区评估入口的预算（`budget`）法定下界由 `20` 放宽至 `10`（上限维持 `20,000`，按 `2` 元彩票单注整数倍偶数凑整），确保四层科学验证基准套件零改动 100% 原样通过。
- **全链路品牌与保密口径**：对外固定使用「优竞体育内部专用」、「扫地僧小高」、「内部说明书助手」；全栈代码、提示词回包与说明书词条严禁出现任何底层大模型厂商/型号标识，严禁出现 `"零风险"` 或 `"单池暗扣"` 违规表述。

### 2. 图文说明书状态解耦、分词检索与网关持久化并发守卫

- **说明书导航与检索纯状态逻辑**：
  - 将「搜索框章节匹配过滤」与「当前激活展示章节（`activeSec`）」彻底解耦：`currentTopic` 直接由 `activeSec` 唯一决定，绝不再因搜索词未命中而回退锁死至问答首页；
  - 当用户点击问答回答卡片内的「📖 跳转查看该功能完整矢量图解 ›」或点击顶部任意章节标签时，立即切换 `activeSec`（若当前搜索词不匹配目标章节则自动清空章节过滤词以避免标签置灰误导），触发 `.manual-body` 滚动置顶，并对目标章节首屏图解卡片施加短暂视觉聚焦高亮脉冲；
  - 章节搜索升级为多词切分与双向子串匹配（例如输入 `"一球小胜卡盘"` 自动切分核心词根，同时命中含 `"一球"` / `"卡盘"` 的词典章节与沙盒章节），并在服务端本地 `0ms` 词库中补齐 `1-2-3` 三步向导、`¥10` 预算边界、看球直觉倾向 `Δ` 与双维协同会诊词条。
- **移动端配额同步与封禁写盘防竞态**：
  - 移动端说明书弹窗挂载与电脑端一致的配额同步回调；
  - 安全网关封禁表持久化定时器在异步写完临时文件后、执行原子改名前，二次校验当前序号是否仍等于启动该次写盘时的最新序号；若已被更新序号超越，立即删除临时文件并放弃改名。

### 3. 双端紧凑屏效、安卓容器安全区校准与外观抽屉归口

- **消除双倍留白与假横条**：
  - 仅在 `embedded === true`（8 皮肤同屏陈列帧）下渲染模拟状态栏与底部 `.home-ind` 仿横条；非内嵌真机 Web 与安卓原生伴侣端一律移除 `.home-ind` 占位；
  - 安卓原生容器识别系统状态栏、导航栏与软键盘内边距并注入网页视口，网页顶栏与底栏采用紧凑单层安全区内边距，杜绝原生内边距与网页固定大留白叠加；
  - 桌面端顶栏压缩为紧凑单行，移除平铺的 8 皮肤胶囊条与重复的打票单入口。
- **「🎨 外观与触感」统一抽屉**：
  - 将 8 套材质皮肤色卡切换、4 档震动波形强度、拟真机械微音效开关及电脑端「📱 8皮肤墙」入口统一整合至顶栏右上角单按钮呼出的「🎨 外观与触感」弹簧抽屉，清空手机 4 页顶栏重复的「🎮超感」按钮与情报账本中段横插的皮肤色卡块。

### 4. 三步精算向导（1-2-3）、自动雷达锚定与按步单主按钮底栏

- **双端向导拓扑**：
  - **电脑宽屏端（`>= 960px`）**：顶栏居中展示可点击切换焦点的 `① 选球定方向 → ② 精算配单 → ③ 审单锁利` 指示器；主工作区三栏从左至右固定为：**左栏 ① 赛事雷达选球**、**中栏 ② 3+1 精算配单**、**右栏 ③ 五维审单锁利 / 情报账本切换**，横跨底部的总控底栏保留全局过关、倍数与查看实票核对单主动作；
  - **手机贴边端（`< 960px`）**：紧凑顶栏内嵌可点按的 `① 选球 → ② 配单 → ③ 审单` 步骤条（底部导航保留 `赛事雷达 | 精算配单 | 审单锁利 | 情报账本` 四签以便直达账本）：
    - **Step ①（赛事雷达）**：显示手动投控栏（过关选择 + 倍数步进 + 应付金额），未选球时提示点选赔率，已选 `>= 1` 场时右侧唯一亮色主按钮引导 **「下一步：② 精算配单 ›」**（并附紧凑「直达审单」辅入口）；
    - **Step ②（精算配单）**：**完全收起底部手动串关悬浮条**，将「套用【当前流派】方案 → 进入 ③ 审单锁利 (¥X)」作为该页底部唯一无遮挡主行动按钮（动态预留底部导航与安全区高度，确保零遮挡）；
    - **Step ③（审单锁利）**：顶部展示当前审单来源状态条，底部投控栏右侧唯一亮色主按钮聚焦 **「🧾 店面防错打票单」**（未满足出票条件时引导「一键合成单关」或「回 ① 补选场次」），卡片底部配「存模拟单 / 记入实买」入账动作；
    - **第 4 页（情报账本）**：收起底部投控悬浮条，全屏纯净展示深度盘面情报流与个人双轨止损账本。
- **选单工作区自动雷达联动契约**：
  - 在应用交互态下开启自动雷达联动（保留无参构造的显式手动模式以兼容既有单元契约测试）：当用户在赛事雷达新增或移除勾选项且未处于「手动纯盘面自由选池覆盖态」时，控制器自动将已选比赛（最多前 8 场）同步至 `targetIds`、置 `anchorToRadarPicks = true` 并刷新 `syncedRadarSig`；当雷达选单清空时自动恢复默认前 2 场纯客观模式；
  - 用户在精算配单顶部点击「已联动雷达 X 场 ▾」折叠条可展开目标对决池，支持手动点选切换为「纯盘面自由选池」或自由增减 1～8 场比赛（此时进入手动选池覆盖态，直至用户点击「恢复联动雷达已选」）。
- **跨页方案移交仪式感动效**：
  - 点击「套用方案」后写入方案移交凭证（含流派名称、总本金、实票张数与时间戳），在切入 Step ③ 审单视图且目标 DOM 实际完成挂载后的下一渲染帧，自动平滑滚至审单顶部、播放步骤条流体点亮与容器扫光礼花，并在审单首屏展示高辨识度方案交接横幅。

### 5. 实用倍数/预算档位、¥10 边界披露与透明直觉倾向 `Δ`

- **倍数与预算档位规范**：
  - 投倍数字键盘快捷预设固定为 `[1, 2, 3, 4, 5, 10]` 倍；
  - 精算配单预算栏提供 `[10, 20, 50, 100]` 元四档快捷键与 `⌨️ 自定义` 内联输入器（输入范围 `10 ~ 20,000`，失焦或确认时自动按 `Math.max(10, Math.min(20000, Math.round(v / 2) * 2))` 对齐为合法偶数彩票金额）；
  - 当非错价雷达席位（如 `¥10` 多场下的【① 稳健保本】）因整数注保本硬约束返回 `available === false` 时，渲染专属「最小保本预算不足引导卡」（提供一键切至 `¥20` / `¥50` 或切往【② 期望效用】按钮），严格与第 4 席「无真错价洼地空仓省钱卡」区分；当某席位因最少独立实票张数 $K$ 使 `totalCost > budget` 时，在金额角标旁披露「$M$ 场覆盖最少需 $K$ 注（¥$2K$）」。
- **看球直觉倾向（`stance`）基准差值契约**：
  - 选单工作区控制器通过注入的服务端计算适配器维护同目标池、同预算、同锚定条件下的 `'objective'`（纯客观）基准方案快照（不在客户端编写任何概率公式）；
  - 当用户切换至 `'home-lean'`（偏主队）或 `'upset-watch'`（防爆冷）时，控制器实时暴露当前席位相对纯客观基准的差值摘要：
    ```ts
    export interface StanceDeltaSummary {
      stance: UserStance;
      ruleNote: string;
      instantRecalcNote: string;
      anchorLockNote: string | null;
      deltaProfitProbPct: number;
      deltaEvPct: number;
      ticketsChanged: boolean;
    }
    ```

### 6. 无截断全赛果盈亏推演明细与「外简内丰」翻转/弹簧组件体系

- **全赛果组合盈亏推演视图**：
  - 废除单行省略截断样式；基于每组互斥场景完整携带的 `legs` 与方案物理实票列表 `tickets`，通过纯集合包含关系（物理实票全部选腿均属于该场景命中腿集合）精确还原该场景命中的全部物理实票行、命中注数与逐票派奖贡献；
  - 每行展示：场景标题（全中/中 $m$ 场 + 命中实票张数）+ 自动换行的全量分场赛果小徽章（`场次 队名 · 玩法[选项@水位]`）+ 发生概率 + 单倍奖/实派总额 + 红绿净盈亏金额与比例条；

- **「外简内丰」双组件与无障碍契约**：
  - **`TactileFlipCard`（双面不透明三维翻转大卡）**：采用 `perspective` 与 `rotateY(180deg)` 弹簧过渡，正反两面统一使用不透明卡片实体底色变量（修补透明皮肤下的透字问题）并通过 `inert` / `pointer-events` 严格隔离背面不可见态焦点；当检测到 `prefers-reduced-motion: reduce` 时自动切换为平面透明度切换；应用于 **Step ② 精算配单总览卡** 与 **Step ③ 五维真相透视舱卡**；
  - **`SpringCollapseDrawer`（物理弹簧手风琴折叠抽屉）**：应用于 **Step ② 目标对决池微调区**、**Step ③ 进阶沙盒与时间差对冲区**（对冲满足 `>= 110` 分钟自动展开，未满足时收拢为单行状态条）、**全赛果单行实票溯源展开** 及 **情报账本单场深度盘面情报卡片**。

- **双维客观协同会诊服务端契约（严守 `ADR-0002` 单向只读隔离）**：
  - 服务端联合会诊上下文构建器直接从权威工作区评估结果中提取结构化配单事实 `actuaryContext`：方案来源类型（`3+1 精算配单` 具体流派、`三模奖金优化` 具体模式、或 `手动未优化等倍串关`）、是否已实现 `0 假中奖倒贴`、单场是否配置同盘双选/卡盘护盾、容错缩水错 1 场回血额 `missOneReturn`、综合抽水率与校准 `EV%` 及物理实票概览；
  - 升级联合会诊系统提示词与返回 JSON 契约（向后保留 `level`、`comboTag`、`summary`、`weakestLeg`、`structureAdvice`、`priceInVerdict`、`perMatch` 全部既有字段），新增双维协同字段：

    export interface XiaoGaoComboPerMatch {

  - 当上游模型仅返回精简字段或启用兜底默认值时，服务端自动根据权威 `actuaryContext` 合成客观准确的 `planContextBadge`、`actuarySynergy` 与 `residualRisks`，确保任何通道状态下绝不出现“对已保本分倍方案盲批未做分倍”的逻辑自相矛盾。

## Testing Decisions

- **好测试的黄金准则**：仅在预确认的高层公开模块接缝处验证用户可观测行为、服务端契约不变量与法定边界，不耦合组件私有状态或内部 DOM 细节，按「一测试一实现（先红后绿）」垂直切片推进。
- **三大公开测试接缝（Seams）**：
  1. **Seam 1 · 服务端运行时、¥10 预算边界与双维协同会诊接缝**（`evaluateQuantWorkspace` / `generateParetoPortfolio`、`createYouJingRuntime` / `createXiaoGaoService`、`createManualQaEngine`）：
