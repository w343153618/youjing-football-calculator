# Spec 0007: 基线六大遗留局限清零与跨端双轨止损账本闭环（Baseline Quirks Resolution & Encrypted Dual-Track Ledger）

Status: `ready-for-agent`
Baseline Anchor: `docs/specs/0000-baseline-spec.md` (`v2.2.0`)
Related ADRs: `ADR-0001`, `ADR-0002`, `ADR-0003`, `ADR-0005`, `ADR-0007`, `ADR-0008`

## Problem Statement

在对 `v2.2.0` 生产基线进行全景代码审计时，梳理出 6 处影响精算严谨度、跨端数据连续性与风控精准度的遗留实现局限：
1. **实盘解析撞名污染与陈旧兜底提示**：解析中国体彩实盘数据时，若真实在售赛事的场次编号（如 `周二002`）与内置演示赛事重名，会误将硬编码的演示排雷简报挂到真实赛事上；同时内置 8 场兜底快照的提示文案仍显示为“周二竞彩 4 场焦点战”。
2. **双轨止损账本缺乏持久化与结算闭环**：个人账本与每日止损护栏仅存于前端内存，页面刷新即丢失并回退为写死的演示条目与静态百分比统计，超止损额度时无防上头拦截引导，且无法对已记方案执行红黑结算或跨手机/电脑同步。
3. **`±2` 深盘让球线下的「一球卡盘率」失真与阈值分裂**：微观精算将让球平去水概率一律视作净胜 1 球概率，导致 `-2 / +2` 等非一球让球线下实际算成了净胜 2+ 球概率；且卡片微标（`52%`）与卡盘提示文案（`50%`）的警示阈值不统一。
4. **推演沙盒与智能不等倍方案互斥回退**：当用户已启用三模奖金优化或套用五流派不等倍方案后，一旦拉动主观胜率信心微调滑块或开启模拟首场腰斩，审单报告会静默退回按统配等倍重算，无法在不改变分倍注单结构的前提下推演真实期望回报率（`EV`）、腰斩回血与单注封顶截断。
5. **早晚场时间差对冲锁利条件过于宽泛**：多场串关未校验中间场次是否在末场开球前完场，且末场在选购总进球、比分或平局时仍按胜平负二分法给出伪无风险对冲提示。
6. **超管解除登录锁定附带清空全局 IP 冷却**：后台执行单账号解锁时会清空所有来源 IP 的密码防爆破计数，可能顺带释放正在撞库其他账号的攻击 IP。

## Solution

在不破坏既有 23 项契约测试与四层安全保密红线的前提下，一次性闭环修复全部 6 项基线遗留问题：
1. 彻底剥离实盘解析与内置演示预警的场次编号耦合，修正内置 8 场快照同步文案；
2. 新增服务端按成员隔离的持久化双轨止损账本深模块（配合客户端离线缓存兜底），支持自定义每日止损护栏（北京时间 `00:00` 自动重置）、超额记实买防上头确认与一键转模拟观察单、订单待开奖/红单/黑单结算与删除，以及实买累计净盈亏、实买红单率、模拟单累计免损金额三项真实统计动态汇总；
3. 对非 `±1` 让球线赛事改用 31 项比分（`CRS`）去水概率精确提取热门方净胜 1 球条件占比，并将全端卡盘警示阈值统一为 `50%`；
4. 让主观胜率信心微调滑块与模拟首场腰斩直接作用于当前已套用的不等倍分倍注单，精确重算每注法定舍入派奖、单注封顶截断、水下状态与线性期望回报率 `EV`；
5. 收紧早晚场时间差对冲锁利门禁：要求全部前序场次开球均早于末场 `>= 110` 分钟（且处于串关可出票态），并严格按末场已选胜平负/让球项匹配无死角互补反向集合（末场为比分/总进球/半全场等局部项时明确标记不可无死角对冲）；
6. 将超管「解除锁定」的 IP 防爆破清理严格限定于目标账号自身关联的失败/登录/已绑设备 IP，同时严守 `ADR-0005` 不触碰 48 小时硬件指纹与传染式 IP 熔断库。

## User Stories

1. 作为内部看盘人员，我希望同步体彩官网实盘赛事时绝不会混入内置教学赛事的虚假伤停预警，仅展示我主动呼叫扫地僧小高生成的真实诊盘结果，以便不被演示文本误导买球决策。
2. 作为离线兜底查看内置赛事的用户，我希望内置快照同步提示准确反映实际的 8 场内置赛事数量，以便信息前后一致。
3. 作为分析 `-2` 或 `+2` 深盘强弱对话的用户，我希望「一球小胜卡盘温度计」准确通过同场 31 项比分去水概率算出强队恰好净胜 1 球（如 `1:0 / 2:1 / 3:2`）在赢球中的真实占比，且微标与底牌提示统一在 `>= 50%` 时高亮预警，以便避免把净胜 2 球率误判为一球卡盘率。
4. 作为已启用「平均优化 / 博热保本 / 博冷高弹」或套用「五流派」不等倍方案的用户，我希望拉动主观胜率信心微调滑块（`-15% ~ +20%`）或打开「模拟首场延期/腰斩（按水位 1.0 算）」时，系统固定当前不等倍各注倍数结构不变，实时重算每张分倍实票的腰斩派奖、法定封顶截断、假中奖组数与真实期望回报率 `EV`（默认 `0%` 分倍态亦使用精确数学期望而非固定抽水近似），以便对即将出票的真实分倍方案做抗压测试。
5. 作为购买 3～8 场串关的用户，我希望早晚场时间差对冲计算器仅在「前 `N-1` 场比赛全部早于最后 1 场至少 `110` 分钟开球」时才激活锁利方案；若存在两场晚场同时开踢，明确提示前序场次未全部完场无法单场锁利，以便防止错误的补单对冲亏损。
6. 作为在末场选择了平局、双选或让球盘的用户，我希望早晚场对冲计算器严格匹配 100% 覆盖剩余赛果空间的互补反向买法（如末场买主胜匹配高返奖的 `让球(-1)让负` 或 `平+客胜` 配平；末场买平局匹配 `主胜+客胜` 配平；末场买双选匹配剩余第 3 项；末场买比分/总进球/半全场局部项时诚实提示无法用单一反向盘无死角对冲），以便确保锁利方案在数学上真正零死角。
7. 作为拥有手机端与电脑端的内部成员，我希望记入的「实买单」与「模拟观察单」按我的登录账号加密持久化在服务端（同时写入本地离线缓存兜底），无论刷新页面还是跨设备登录都能看到完整一致的个人账本，且新账号初始账本干净无写死假数据，以便长期真实复盘。
8. 作为注重资金纪律的成员，我希望在账本页随时查看并自定义我的「每日止损护栏」上限（默认 `¥300`，跨北京时间 `00:00` 自动恢复满额可用额度）；当点击「记入实买」的金额超出今日剩余止损额度时，系统弹出醒目防上头拦截提示，提供「一键转为 0 成本模拟观察单」与「确认超限仍记入实买」两个明确选项，以便在逆风期有效管住双手。
9. 作为复盘历史注单的成员，我希望可对账本中的每笔记录切换结算状态（`待开奖`、`红单中奖` 支持默认保底派奖或输入实际中奖金额、`黑单未中`）或删除误记条目，并实时看到顶部三块统计卡动态汇总我的**实买累计净盈亏**、**实买红单率**与**模拟单累计免损金额**（模拟观察单标记为黑单未中时累加其规避的拟投本金），以便直观量化精算纪律带来的真金收益与免损价值。
10. 作为超级管理员，我在总控台对某位输错密码被冷却的成员点击「🔓 解除锁定」时，系统仅解除该成员账号及其关联来源 IP 的登录冷却，绝不清空其他陌生攻击 IP 的防爆破锁定记录，且绝不越权清空 48 小时硬件/IP 熔断库，以便确保风控隔离严密。

## Implementation Decisions

- **实盘解析纯净性**：移除实盘 JSON 解析器中按 `matchNumStr` 回查内置演示赛事 `aiAlert` 的逻辑；实盘赛事初始 `aiAlert` 恒为空，仅由服务端会话级 `aiAlerts` 合并用户真实触发的扫地僧小高诊盘结果；内置兜底 `syncNote` 动态输出内置赛事实际场数。
- **全让球线兼容的一球卡盘率计算**：当赛事 `HHAD` 在售且让球线绝对值恰好为 `1`（`-1` 或 `+1`）时，沿用 `HHAD` 让球平去水概率与热门方胜率比值；当让球线绝对值不为 `1`（如 `-2 / +2`）或 `HHAD` 停售时，利用同场 `CRS` 31 项比分去水概率计算热门方全部赢球比分中净胜球差恰好为 `1`（主热 `1:0, 2:1, 3:2`；客热 `0:1, 1:2, 2:3`）的条件占比 `crsOneGoalWinProb / crsTotalWinProb`（上限截断 `0.85`）；统一将 `microBadges` 与 `cardPanTip` 的警示阈值对齐为 `>= 0.50`。
- **不等倍方案沙盒推演管道**：在工作区评估器中，三模奖金优化与五流派先基于未腰斩、`0%` 偏移的基准盘口确定各实票行的整数倍数分配；随后统一通过沙盒变换对 `appliedPlan` 的每条实票腿应用首场腰斩（首场赔率置 `1.0`）与主观胜率偏移（`baseProb * (1 + delta / 100)`，夹逼 `[0.02, 0.96]`），重新执行单注 `BigInt` 银行家舍入、法定单注封顶截断（记录真实 `cappedClipped`）与行派奖汇总。无论滑块是否偏移或腰斩是否开启，只要存在有效 `appliedPlan`，`effectiveReport` 始终由该沙盒化后的不等倍方案生成，且期望回报率统一按线性期望精确计算 $\text{EV} = (\sum l.\text{prob} \times l.\text{returnPayout} - \text{totalCost}) / \text{totalCost}$。
- **严谨早晚场时间差对冲判定**：
  - 仅在 `pickedMatches.length >= 2`、`report.canCheckout === true` 且过关方式非纯单关时评估对冲；
  - 将已选赛事按开球时间升序排列后，要求倒数第 2 场（即最晚的前序场次）与最后 1 场的间隔 `>= 110` 分钟，确保末场开球前其余所有串关腿均已完场；
  - 严格检查末场全部已选选项能否由末场在售 `HAD / HHAD` 构成 100% 互补无死角反向组合（单选主胜、客胜、平局、让球单选、`HAD/HHAD` 同池双选均精确映射单选或双选调和等效水位反向盘，并择高水位入口降低对冲成本；若末场含比分、总进球、半全场或跨盘无法构成完备划分，则返回 `available: false` 与明确原因说明）。
- **独立双轨止损账本服务端深模块**：
  - 构建独立服务端账本管理模块（持久化至 `data/ledgers-db.json`，采用 `0o600` 临时文件原子替换刷盘，支持注入 `nowFn` 与文件路径接缝），挂载至统一运行时装配器；当超管删除账号时同步清理该账号账本记录；
  - 登录握手（`/api/security/bootstrap` 已认证分支与 `/api/auth/login`）直接在加密工作区包中附带当前用户的 `ledger` 快照（零额外往返）；新增单一加密认证路由 `POST /api/ledger/mutate`（通过统一 `runEncryptedRoute` 鉴权拆封），支持 4 类原子动作：
    1. `set-daily-limit`：更新每日止损上限（`20 ~ 100,000` 整数元），按 `UTC+8` 北京时间自然日实时重算当日已用实买额与剩余额度；
    2. `add-entry`：新增 `live`（实买单）或 `paper`（模拟观察单，记录 `cost: 0` 与规避参考本金 `paperRefCost`）；当新增 `live` 且 `cost > dailyRemaining` 且未传 `forceConfirmed: true` 时，拒绝直接入账并返回结构化超限预警 `{ ok: false, code: 'STOP_LOSS_EXCEEDED', dailyRemaining, dailyLimit, overBy }`，由前端弹出防上头拦截卡供用户选择「一键转为 0 成本模拟观察单」或「确认超限仍记入实买（`forceConfirmed: true`）」；
    3. `settle-entry`：将指定账本条目标记为 `pending`、`won`（实买单支持传入实际中奖派彩金额，默认带入保底派奖，计算净利 `settledReturn - cost`）或 `lost`（实买单净利 `-cost`；模拟观察单标记为未中时将其 `paperRefCost` 计入累计免损金额）；
    4. `delete-entry`：删除指定账本条目并重算当日剩余止损额度与汇总统计；
  - 前端移除硬编码演示账本与静态强弱项数字，按当前登录 `userId` 将最新 `ledger` 快照同步镜像至 `localStorage` 作为断网离线展示兜底。
- **精准作用域的超管登录解锁**：在账号记录上追踪最近一次密码输错来源 IP（`lastFailedIp`）；执行 `unlock-login` 时仅从内存 `ipBruteMap` 中移除该账号关联的 `lastFailedIp`、`lastLoginIp` 及已绑定设备的 `lastIp`，保留其他无关 IP 的防爆破冷却状态。

## Testing Decisions

- **好测试的准则**：严格通过模块的公开接缝验证外部可观测业务结果与独立手算精算真值，禁止耦合内部私有辅助函数或编写同义反复断言。
- **核心测试接缝（Seams）**：
  1. **精算内核公开接缝（`parseSportteryRawJson`、`fetchOfficialMatchesServer`、`analyzeMatchMicroQuant`、`evaluateQuantWorkspace`、`computeProOrderInsights`）**：验证实盘 `周二002` 不被注入演示 `aiAlert`、`-2 / +2` 让球线下基于 31 项比分的精确一球卡盘率与 `50%` 微标阈值、启用博热保本/五流派后拉动信心滑块与开启首场腰斩保持不等倍注数结构并精确输出 `EV` 与封顶截断、以及 3 场含双晚场或末场总进球时拒绝伪锁利而前序全早场 + 末场互补盘时精确算出锁利净利。
  2. **账号防爆破隔离接缝（`createAccountManager`）**：验证两个不同 IP 同时触发密码连错冷却后，对账号 A 执行 `unlock-login` 仅恢复账号 A 及其对应 IP 登录能力，攻击账号 B 的另一 IP 依然保持 `429` 冷却锁定。
  3. **全栈加密账本运行时接缝（`createYouJingRuntime` + `/api/ledger/mutate` + `/api/auth/login`）**：通过完整 `AES-256-GCM` + `HMAC-SHA256` 信封验证新成员初始零假数据账本、跨会话持久化、自定义每日止损上限与跨北京时间 `00:00` 自动满血重置、超止损额度未确认拦截与一键转模拟观察单、实买红/黑结算与模拟单黑单累计免损统计、删除条目回退当日额度及跨账号严格隔离。

## Out of Scope

- 自动联网抓取赛果自动开奖结算（账本结算保持由内部成员手动点击红/黑确认并支持填写实派金额）。
- 修改任何中国体彩法定算奖规则、安全熔断时长（48 小时）或底层主备语义网关模型配置。
