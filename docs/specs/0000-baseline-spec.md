Status: `baseline-locked`
Baseline Version: `v2.2.0` (`66de3ed`)
Related ADRs: `ADR-0001` ～ `ADR-0008`
Canonical Vocabulary: `GLOSSARY.md`

> **基准规范定位**：本文档对「优竞体育内部专用」当前线上生产基线（`v2.2.0`）的全部用户可见功能、权限模型、数据结构、加密网关协议、中国体彩法定算奖规则、核心精算公式与跨端交互状态机进行 **1:1 忠实固化**。任何后续增量需求（`0007+`）均以本基线为唯一现状参照；当前代码与理想业务语义之间的已知偏差统一在文末 **《已知实现局限与待演进项（Known Quirks & Debt）》** 中备案。

## Problem Statement

普通竞彩计算工具（含中国体彩官方计算器）仅展示单一的“理论最高奖金”，向购彩者隐去了五大玩法暗扣抽水率（`11%~22%`）、剔除水分后的真实隐含概率、复式与多串过关中的「假中奖组合（中奖实派低于总本金）」、热门强队「一球小胜卡盘」风险以及赛前利好消息是否已被水位提前榨干（消息入价消化度）。同时，内部专业团队在日常高频看盘、配单与线下体彩店打票场景中，还需要兼顾手机单手触控与电脑宽屏同屏分析、严格的内部账号授权计费与设备防共用管控，以及抵御外部爬虫、AI 读链器与同行逆向扒取核心策略源码的纵深安全防线。

---

## Solution

构建「优竞体育内部专用」多端一体化智能精算与风控工作台（Web 手机端 `< 960px` 贴边四页签 + Web 电脑端 `>= 960px` 三栏同屏工作台 + 安卓原生伴侣端 APK）：
1. **服务端精算与风控黑盒**：将中国体彩法定规则引擎（`四舍六入五成双`、四档单注封顶、同场单一玩法互斥、`4/6/8` 关上限、自由过关与 `M串N` 互斥赛果状态空间枚举）、单场微观精算（预期进球 `xG`、一球卡盘率、同义错价替换）、五维真相审单、三模奖金优化、1～8 场五流派战术配单、早晚场时间差对冲锁利全部收敛于服务端内存黑盒，前后端通过会话级 `AES-256-GCM` 密文信封与端点绑定 `HMAC-SHA256` 防重放签名通信。
2. **算术与情报物理隔离**：确定性数学计算与「扫地僧小高」双模靶向排雷（单场独立点诊 + 多场联合串关会诊 + 消息入价消化度研判）严格解耦；语义网关采用主力模型优先、异常无感切换备选模型并自动探测回切的高可用架构，对外全链路零底层模型字样暴露。
3. **闭环账号授权与四层反逆向防线**：实施全员前置登录门禁、首次激活计时、双设备指纹限绑、365 天长期免登与断网保护、内嵌式隐形超管总控台、说明书铁笼问答（2 小时内累计违规 `> 4` 次自动锁号）以及 48 小时跨浏览器硬件指纹与传染式 IP 整机熔断天平。
4. **超感触觉交响体验**：耦合 240Hz 固定子步长弹簧动力学、8 套视觉材质专属轴体、三通道触感反馈（安卓原生线性马达桥接 / Web 多段波形 / iOS Switch Taptic / WebAudio 拟真微声场）及 3D 陀螺仪防错打票核对单。

## User Stories

### 一、通行门禁、会话韧性与隐形超管管控
1. 作为未登录访客，我打开工作台时仅能看到「优竞体育内部专用」通行登录框，浏览器网络面板中不接收任何赛事水位、五流派或精算数据，以便彻底杜绝未授权外部人员窥探内部盘面工具。
2. 作为新开通的内部成员，我希望管理员建号后我的可用时长不会提前流逝，只有在我第一次成功输入账号密码登录瞬间才正式启动倒计时（首次激活计时），以便获得足额的授权体验周期。
3. 作为内部成员，我希望首次登录成功后获得长达 365 天的免重复输密状态（长期免登态），且在地铁/电梯短暂断网或 WiFi 切 5G 时界面保持在线状态并提示离线保护、恢复联网后自动静默续接会话，以便高频看盘不被频繁重登打断。
4. 作为拥有手机与电脑的内部成员，我希望同一账号可在最多 2 台常用设备（默认上限，可由超管单独调整）绑定使用，而第 3 台陌生设备尝试登录时被自动拦截，以便兼顾双端办公与防多人转发共用。
5. 作为不小心输错密码的成员，我希望前 4 次输错时明确提示剩余容错次数，连续第 5、6、7、8、9+ 次输错时按 `1分钟 / 5分钟 / 15分钟 / 1小时 / 24小时` 阶梯式冷却保护而非直接永久废号，以便兼顾防撞库安全与误操作容错。
6. 作为普通成员，我登录后的界面顶栏、抽屉与 DOM 中看不到任何后台管理按钮或管理员字样，以便减少试探攻击面。
7. 作为超级管理员，我登录后顶栏与账本区自动显现「👑 总控台」入口，可一键创建成员账号（支持 `2h / 24h / 3d / 7d / 30d / 自定义小时 / 永久`）并复制微信发卡口令、加时续期、转永久、一键解绑换机设备、独立开关智能权限并调整每日配额、重置密码、启停/删除账号、解除登录锁定、修改超管自身密码，以及查阅最近 150 条安全风控与违规提问原文日志，以便在一个工作台内完成全员运营管控。

### 二、实盘同步、赛事雷达与中国体彩法定选号
8. 作为内部看盘人员，我希望进入工作台或手动点击「同步水位」时获取中国体彩在售赛事的五大玩法（胜平负、让球胜平负、总进球、半全场、31 项全比分）最新水位及红升（`▲`）绿降（`▼`）变动箭头，以便第一时间捕捉官方调水风向。
9. 作为看盘人员，我希望在每场赛事卡片与赔率按钮内直接看到剔除抽水后的真实隐含概率百分比、双方预期进球 `xG`、一球小胜卡盘率、主盘与半全场抽水对比及同义省钱差价微标，以便一眼识别盘口水分与结构特征。
10. 作为看盘人员，我希望支持按玩法视图（`混合 / 胜平负 / 比分 / 进球 / 半全场 / 单关`）、快捷特征（`全部 / ⚡单关 / 浅抽水 / 🔻急降水 / 省钱差价`）及联赛多选快速筛选赛事，并可一键载入教学演示场景（假中奖、早晚锁利、4串1雪崩），以便快速定位目标盘面。
11. 作为购彩选号人员，我希望同一场比赛在同一玩法内支持复式多选，但在混合过关或串关模式下点击同场另一玩法时被「互斥」锁止拦截并给出规则提示，以便 100% 避免选出体彩店终端机无法出票的同场跨玩法废单。
12. 作为单关购彩人员，我希望在「胜平负」或「单关」视图下，若全单所有已选项及目标同场的胜平负与让球胜平负均开放单关（标有「单」字），系统允许同场双选这两个玩法并自动将过关方式锁定为【单关】（最多支持同时选 15 场全单关赛事；串关模式严格限制最多 8 场），且切回混合等其他视图时自动裁剪同场多余玩法，以便完整对齐中国体彩官网单关规则。
13. 作为选择未开售或单场非单关选项的用户，我希望未开售盘口置灰标「未」禁选；若仅选了 1 场未开单关的比赛，底栏与审单台明确显示应付 `¥0`、不可出票并提示「还差 1 场凑 2串1」，同时在审单台提供一键切换该场半全场「合成单关」的救场按钮，以便在不想硬凑串关时借道单场出票。

### 三、全局常驻投控栏、自由过关与 M串N 多串容错
14. 作为跨页面看盘的用户，我希望无论在电脑宽屏三栏滚动，还是在手机端切换「赛事雷达 / 五流派 / 审单锁利 / 情报账本」任一页签，底部始终固定常驻展示已选场数、过关选择、投注倍数、应付金额与真实保底～最高奖金区间，以便随时掌控核心投控杠杆。
15. 作为串关用户，我希望点开「过关选择」浮层后，既能在 8 格自由过关（`单关`、`2关`～`8关`）中多选叠加拆票，也能在选满 `3~8` 场时一键选用中国体彩官方标准 `M串N` 多串容错组合（`3串3` 至 `8串247`），且当选单包含总进球（限 6 关）或比分/半全场（限 4 关）时自动禁用超限关数并说明原因，以便灵活构建防黑 1～2 场的容错方案。
16. 作为调倍用户，我希望通过 `− / +` 步进或九宫格数字键盘在 `1 ~ 999` 倍间自由调节倍数（超出单票 99 倍自动提示拆票张数；单次总额超 `¥6,000` 提示理性购彩，超 `¥20,000` 法定硬上限时标红拦截出票）；而在启用三模奖金优化或套用五流派后，倍数区自动切换为「⚖️ 智能分倍中」双态（支持 `×2倍扩仓` 与 `还原等倍`），以便消除统配等倍与智能不等倍的语义冲突。

### 四、五维真相审单、三模奖金优化与进阶锁利工具
17. 作为审单人员，我希望在「五维真相透视舱」同时看到 6 块核心仪表：真实保底奖金（划掉官网虚高最高奖）、60% 高概率到手落点区间、真赚钱率 vs 表面命中率、假中奖倒贴组数及占比、综合暗扣抽水与合成等效水位、危险分（`8~99` 分）与连黑 5 次概率及建议仓位上限，以便在出票前看穿方案真实数学底牌。
18. 作为复式或多组合投注用户，我希望一键切换「① 平均优化」、「② 博热保本」、「③ 博冷高弹」三种智能分倍策略，并通过实时弹簧生长的动态奖金天平柱状图（含本金红线对比）及逐行「四舍六入五成双」组合盈亏明细表直观核验每组净利，以便消灭假中奖并按看球把握度精准倾斜利润。
19. 作为追求极致性价比的用户，我希望审单台自动检测并提示四项可一键执行的纠偏动作：弹性全保本升级预算建议、未开单关单场的半全场合成单关替换、同义错价高水入口无损替换（如 `总进球0球` 对比 `比分0:0`、`让负(-1)` 对比 `平+客胜` 配平），以及拉低整单真赚钱率 `>= 14%` 的“拖油瓶”短板场一键剔除，以便省钱增收。
20. 作为实战串关玩家，我希望当所选早场与晚场开球间隔 `>= 110` 分钟时，早晚场时间差对冲计算器自动算出“假设早场命中后去店里补买晚场反向盘的具体金额与锁定净利润”，以便在凌晨开赛前提前锁死收益安心休息。
21. 作为手握临场独家情报或担心极端天气的用户，我希望在推演沙盒中左右拉动「主观胜率信心微调滑块（`-15% ~ +20%`）」实时观测期望回报率 `EV` 何时由负转正，并可开启「模拟首场延期/腰斩（按水位 `1.0` 算）」预演剩余串关能否包住本金，以便量化决策边界。

### 五、1～8 场五流派智能配单与雷达选队锚定
22. 作为寻找最优买法结构的成员，我希望在目标对决池自由圈定 `1 ~ 8` 场比赛、设定目标预算（`¥50 / ¥100 / ¥200 / ¥500`）与看球倾向（`纯客观 / 偏主队 / 防爆冷`），自动获取五大战术流派方案（铁盾保本流、博胆护盾流、容错防爆流、进球结构流、错价刺客流），且错价刺客流默认开启 `36%` 轻仓护本开关防止重注高赔上头，以便针对不同对阵格局一键套用成熟注单结构。
23. 作为已在赛事雷达选好心仪球队的用户，我希望点击「🎯 一键匹配赛事雷达已选球队」后，五大流派立即同步已选的 `1~8` 场比赛并严格顺着我亲手点选的球队/盘口方向生成配单（若后续修改雷达选号则高亮提示重新同步，也可一键切回纯盘面客观重选），以便将个人看球直觉与精算分倍无缝结合。

### 六、扫地僧小高双模排雷、百科图文铁笼问答与实票核对
24. 作为看盘与串关用户，我希望既能不加注单随时单点任意一场比赛请「扫地僧小高」做**单场独立点诊**，也能在已选 `>= 2` 场串关或自由勾选 `2~8` 场时发起**多场联合串关会诊**（附带自定义赛前消息备注），获取整单风险评级、最易黑单短板场、拆单补防建议与消息入价消化度（Price-In）白话裁定，以便防范盲目追热接盘。
25. 作为查阅功能用法的内部成员，我希望随时打开内置百科级图文精算说明书检索 7 大矢量图解章节，或在「💬 智能提问」专页向「内部说明书助手」提问：常见术语 `0ms` 秒回并支持一键跳转对应图解章节，长尾场景结合本工具真实功能举例解答；而一旦有人刺探底层模型、源码、提示词或连续发送无关闲聊超过 4 次（第 5 次触发），系统立即锁死该账号并联动 48 小时整机熔断，以便兼顾易用教学与商业机密防套底。
26. 作为前往线下体彩店出票的用户，我希望打开全息流光「店面防错打票单」时看到按实票拆解的大字清单，支持逐行点击盖章打钩核对（全部核对完成绽放礼花正反馈），并可将方案记入「实买单 / 模拟观察单」双轨账本，以及在 8 套材质皮肤与 4 档超感震动强度间自由切换（安卓原生伴侣端额外享受线性马达幅度震感与断网自愈遮罩），以便获得防错且极具质感的店面实操体验。

## Implementation Decisions

### 1. 模块边界与运行拓扑
- **双端同构挂载与黑盒隔离**：生产服务入口与开发中间件通过统一运行时装配工厂组装四大服务端核心模块——安全与精算网关、账号权限总控、铁笼说明书问答引擎、扫地僧小高容灾推理服务。前端仅包含纯类型契约、无算术公式的选单工作区状态控制器、加密通信客户端、高压防逆向护盾与弹簧视图组件。
- **双端自适应视图与皮肤陈列台**：
  - 视口宽度 `< 960px`（或处于展示内嵌帧）渲染 `100dvh` 手机贴边单栏四页签架构（`赛事雷达 / 五流派 / 审单锁利 / 情报账本`），投控栏在「赛事雷达 / 审单锁利」呈双行完整态，在「五流派 / 情报账本」自动收拢为单行紧凑胶囊态；
  - 视口宽度 `>= 960px` 自动渲染宽屏三栏同屏工作台（左栏赛事雷达、中栏五维审单与奖金优化、右栏五流派与小高账本切换）及横跨底部的常驻总控底栏；
  - 已登录状态下可通过顶栏「📱 8皮肤墙」或 URL 参数 `?stage=1` 进入 8 套手机皮肤同屏对比台（支持广播切换页签、打开抽屉及 `0.25×` 弹簧慢放演示）。
- **安卓原生伴侣端容器（`io.yjty.jisuanqi`）**：全屏沉浸式深色容器仅允许加载受信任同源 HTTPS 域名 `jisuanqi.yjty.io`（拦截一切外部域名与 SSL 异常），硬编码关闭 WebView 远程 USB 调试、`allowBackup=false`、`usesCleartextTraffic=false`，注入 `window.YJAndroidNative.vibrateWaveform(patternCsv, amplitude)` 原生线性马达接口，在 `onPause / onStop / onDestroy` 强制刷盘持久化 Cookie，并通过系统网络回调提供断网暗色遮罩与恢复联网无感重载。

### 2. 四层纵深安全、加密信封与 48 小时整机熔断契约
- **请求分流与前置门禁顺序**：
  1. `GET /api/health`：返回脱敏健康状态 `{ ok: true, version, uptimeSec }`（零品牌词）；直连回环地址访问 `GET /api/xiaogao/status` 供部署脚本自检主备通道状态；
  2. `GET /robots.txt`：声明屏蔽主流爬虫、AI 阅读器与 `/internal-export-trap` 路径；
  3. **蜜罐陷阱路由**：凡访问 `/internal-export-trap`、`/.env`、`/.env.local`、`/.git/config`、`/wp-admin`、`/source.map`、`/api/v1/export-strategy-dump` 之一，立即触发 48 小时 IP 熔断并返回 `403` 阻断页；
  4. **48 小时熔断拦截**：检查来源 IP、`X-YJ-Sid` / `yj_sh_sid` Cookie、`X-YJ-Hw` 硬件指纹是否命中封禁表；若已封禁的 `hwFp` 切换了新网络 IP 请求接口，触发**传染式封禁**将该新 IP 一并锁入 48 小时封禁表；

### 4. 实盘同步、中国体彩法定规则与精算数学公式
- **服务端三层水位同步与五大奖池建模**：
  - 服务端按 `120s` 内存缓存周期（手动点击「同步水位」强制穿透）请求中国体彩 `getMatchCalculatorV1.qry?channel=c`（`4.5s` 超时）→ 失败读取磁盘 `sporttery-snapshot.json` → 再失败回退内置 8 场 `FALLBACK_MATCHES`；
  - 每场赛事完整解析五大奖池：`HAD`（胜平负 3 项）、`HHAD`（让球胜平负 3 项，含 `goalLine`）、`TTG`（总进球 `0球`～`7+球` 共 8 项）、`HAFU`（半全场 9 项）、`CRS`（全场比分完整 **31 项**，含主胜 12 项 + `胜其它`、平 4 项 + `平其它`、客胜 12 项 + `负其它`），独立标记各奖池 `selling` 开售状态、`single` 单关资格与水位升降 `trend`（`1` 红升 / `-1` 绿降 / `0` 平稳）；
  - 同步刷新时，前端工作区按 `matchId` 或 `matchNumStr` 自动对齐保留用户已勾选选项并更新最新水位与单关标记。
- **去水真实隐含概率与单场微观精算（`microQuant`）**：
  - 奖池返还率 $\text{payoutRatio} = \frac{1}{\sum (1 / \text{odds}_i)}$，暗扣抽水率 $\text{vig} = \max(0, 1 - \text{payoutRatio})$，各选项真实隐含概率 $\text{fairProb}_i = \frac{1 / \text{odds}_i}{\sum (1 / \text{odds}_j)}$；
  - **预期进球（`xG`）**：由总进球 `TTG` 各档去水概率加权求和得到总预期进球（`0~6球` 按对应球数、`7+球` 按 `7.3` 球加权，缺失时默认 `2.45`），再按主队实力占比 $\text{strengthShare} = \frac{P_h + 0.5 P_d}{P_h + P_d + P_a}$ 切分 $\text{homeXG} = \text{totalXG} \times (0.18 + 0.64 \times \text{strengthShare})$，$\text{awayXG} = \max(0.25, \text{totalXG} - \text{homeXG})$；
  - **一球卡盘率**：取 `HHAD` 让球平去水概率 $P_{hd}$ 与热门方独赢概率 $P_{\text{fav}}$（受让 `+` 取客胜 $P_a$，让球 `-` 取主胜 $P_h$），计算 $\text{oneGoalShareOfWins} = \min(0.85, P_{hd} / P_{\text{fav}})$；`>= 50%` 时生成防让平卡盘警示；
  - **黄金进球带与半场平局率**：遍历相邻两档总进球去水概率之和取最大对作为 `topTwoGoals`；汇总半全场 `dh / dd / da` 去水概率之和作为 `halfDrawProb`；
  - **同义错价替换（`arbitrages`）**：自动检测三组等价入口差价——① `总进球·0球` 对比 `比分·0:0`（绝对水位差 `>= 0.15`）；② `goalLine === '-1'` 时 `让球(-1)·让负` 对比 `胜平负[平+客胜]` 调和合成等效水位 $\frac{1}{1/O_d + 1/O_a}$（差值 `>= 0.02`）；③ `goalLine === '+1'` 时 `让球(+1)·让胜` 对比 `胜平负[主胜+平]` 调和合成等效水位（差值 `>= 0.02`）。若用户当前选单恰好命中劣势项且未选优势项，审单台弹出 `activeSwapTip` 支持一键无损替换。
- **中国体彩法定选号、算奖与状态空间枚举引擎**：
  - **单注计奖舍入与封顶**：单注基础金额 `2 元`，使用 `BigInt` 将每关赔率放大 `10,000` 倍精确连乘后，严格按 `GB/T 8170` 执行**四舍六入五成双，五后非零则进一**保留至分，再按该注实际关数执行法定单注封顶（单关 `10万`、`2~3关 20万`、`4~5关 50万`、`6~8关 100万`），最后乘以单注整数倍数得到该注实派金额；
  - **选号门禁与关数上限**：同场同玩法可多选；串关严禁同场跨玩法混选；仅在 `spf / single` 视图且全单所有已选项均开单关时允许同场 `HAD + HHAD` 双选或总场数达 `9~15` 场（均自动强制锁定 `passSizes: [1]` 单关，超 `15` 场硬拦截）；各玩法最高串关上限固定为 `HAD/HHAD: 8`、`TTG: 6`、`HAFU/CRS: 4`，整单最高可串关数 `poolCap` 自动取已选玩法上限最小值；单次订单总额 `> ¥6,000` 告警、`> ¥20,000` 拦截禁止出票；
  - **自由过关与 27 种官方 `M串N` 拆票**：支持自由过关 `1~8` 关多选叠加，以及 `3串3 / 3串4`、`4串4~4串11`、`5串5~5串26`、`6串6~6串57`、`7串7~7串120`、`8串8~8串247` 共 27 种标准多串组合（复式选号下先对 $M$ 场取单场各 1 项笛卡尔积生成 $M$ 场组合票，再逐张按组合关数拆解子串关，带 `512` 元组与 `2,048` 基础注单保护上限）；
  - **互斥赛果状态空间精算**：
    - 纯满串（单关数且等于总场数）：各注单天然互斥，直接逐注核算；
    - 纯单关模式：单场同玩法按去水概率求和（上限截断 `0.995`）；同场 `HAD + HHAD` 双单关按净胜球差 `[-3..+3]` 经验分布枚举同时命中的物理兼容注单集合；`<= 8` 场且状态数 `<= 2,048` 时精确枚举跨场组合，否则按 `O(M)` 线性汇总单场保底与全红极值；
    - 自由过关多选与 `M串N` 多串：将每场比赛归一化为「命中某一所选选项」或「未命中」的互斥状态空间；总状态数 `<= 2,048` 时精确遍历全部命中场数 `>= kMin` 的状态向量并汇总该状态下同时命中的全部子注单派奖，从而确保总中奖率 `anyWinProb` 绝不突破 `100%`，并精确剥离「局部命中但总派奖低于全单总本金」的多串假中奖组合；当复式状态数 `> 2,048` 时退化为遍历 `2^M` 场次命中子集并按高低赔极值双档（`0.55 / 0.45`）加权估算；
  - **五维审单派生指标**：60% 高概率落点带取按发生概率降序前 `ceil(0.6 * K)` 组的派奖极值区间；危险分公式为 $\text{clamp}(8, 99, \text{round}((1 - P_{\text{profit}}) \times 58 + \max(0, \bar{L} - 1) \times 9 + \text{UW}_{\text{share}} \times 22))$；拖油瓶体检在剔除单场过关率最低的一关后若胜率跃升 `>= 14%` 即触发砍场提示；早晚场对冲在已选 `>= 2` 场且首尾开球间隔 `>= 110` 分钟时，按 $\text{targetReturn} / O_{\text{opp}}$（凑整为 `2` 元偶数倍）计算反向补单本金与锁定净利。

### 5. 三模奖金优化与 1～8 场五流派配单引擎
- **三模奖金优化（`optimizeBonusPlan`）**：
  - 基准总预算取手动总本金、弹性全保本升级本金与 `6k` 元三者最大值，折算总注数后按概率降序对每张基础注单分配整数倍：
    1. **平均优化（`equal`）**：按各注单倍封顶后派奖额 `1 / unitPayout` 反比例分配倍数；
    2. **博热保本（`hot-first`）**：第 `2..k` 个低概率次选注仅分配覆盖目标总本金的最小保本整数倍 $\lceil \text{targetStake} / \text{unitPayout}_i \rceil$，剩余全部注数重砸向第 `1` 高概率主攻注；
    3. **博冷高弹（`cold-first`）**：前 `1..k-1` 个正路/中赔注仅分配保本整数倍，剩余全部注数重砸向最低概率的最高赔冷门注；
  - 当方案合成等效水位 `> 1.02` 时，执行最多 `64` 轮水下垫高修补消除假中奖（单注初始分配上限 `99` 倍；启用后支持按比例 `scaleMultiple` 扩仓，单注最高卡 `999` 倍）。
- **1～8 场五流派战术配单（`generateFiveArchetypes`）**：
  - 支持目标对决池自由圈定 `1 ~ 8` 场比赛、预算 `¥20 ~ ¥20,000`（偶数凑整）、三档看球倾向（`home-lean` 对主向概率乘 `1.08` 上限 `0.88`；`upset-watch` 对平/受让/客向概率乘 `1.12` 上限 `0.75`）以及**赛事雷达选队锚定（`anchorToRadarPicks`）**——开启锚定时优先将用户在赛事雷达已勾选比赛排在前列，并严格沿用用户所选玩法方向构建主攻腿与次选防冷腿；
  - 五大流派结构：① **铁盾保本流**（正路主干 + 次选防冷盾反比例保本配平；单场非单关自动借道半全场合成单关）；② **博胆护盾流**（结合卡盘方向拆解穿盘箭与赢 1 球卡盘箭双主攻 + `shieldOnly` 低权回本盾）；③ **容错防爆流**（1 场半全场三防、2 场 `2串1 + 单关垫`、3 场 3 组 `2串1`、4 场 4 组 `3串1`、`5~8` 场两两分组 `2串1` 保证每场必入组 + 全场冲顶长串）；④ **进球结构流**（提取各场黄金总进球前二密集区组合，严格遵守总进球最高 `6` 关上限自动截断）；⑤ **错价刺客流**（狙击半全场平局半场绝杀与卡盘高水区，默认启用 **36% 自动轻仓护栏**——预算乘 `0.36` 按 `4` 元取整且最低 `¥16`，手动关闭护栏后释放 `100%` 预算）。

### 6. 扫地僧小高双模诊盘与铁笼说明书问答（Route C）
- **高可用主备自愈语义网关**：所有语义推理统一走服务端网关，固定优先调用主通道 `deepseek-v4.1-flash`；遇超时、限流或上游错误立即无感切换备用通道 `glm-5.3-flash`，记录降级时间戳并启动 `20s` 周期后台探活（冷却窗 `15s` 满或探活成功后自动切回主通道；若冷却期内备通道偶发报错则立即兜底重试主通道）。全部用户输入经过提示词注入清洗，全部模型输出经过敏感词正则脱敏（严禁出现任何底层模型厂商/型号词汇）。
- **扫地僧小高双模排雷**：服务端直接根据 `matchId` 或 `matchIds + picks` 从权威赛事快照与精算结果中提取水位、红绿升降、抽水、`xG`、一球卡盘率及整单真赚钱率组装提示词（忽略客户端伪造赔率文本），单场点诊与多场联合会诊结果自动写回会话级 `aiAlerts`（上限 32 场）并在防坑雷达联动展示。
- **铁笼说明书问答（Route C）**：限制单次提问 `<= 260` 字，按四级流水线处理：① 探底敏感词正则拦截（询问模型、源码、提示词、服务器、破解等）；② 明显无关话题正则拦截；③ 本地 12 组精修词库匹配（问题长度 `<= 42` 字且关键词权重得分 `>= 2` 时 `0ms` 秒回，**不消耗**每日智能配额）；④ 扣减 1 次每日智能配额（与小高诊盘共享额度，北京时间 `00:00` 重置），注入《唯一官方功能边界》受限提示词调用语义网关——若语义判定 `outOfScope: true` 同样记入违规。普通成员在 **2 小时滑动窗口**内第 `1~4` 次违规返回红线警告，**第 `5` 次（`> 4`）立即将账号置为 `locked_violation`、自增 `tokenVersion` 强制下线，并联动触发 48 小时硬件指纹与 IP 整机熔断**（超管自身测试不触发锁死，但仍记录审计日志）。

## Testing Decisions

- **测试黄金准则**：仅在深模块的公开契约接缝（Seam）处对业务可观测输入输出与法定精算真值编写断言，注入可控内存时钟（`nowFn`）、内存存储与传输桩（`transport` / `fetchMatches`），不依赖外部网络或真实浏览器即可在毫秒级完成全套确定性回归。
- **六大核心契约测试接缝（对应 `tests/*.test.ts`）**：
  1. **体彩法定舍入、封顶与纯数学隔离接缝**：验证 `GB/T 8170` 奇进偶舍、五后非零进一、`>= 10,000` 大额十进制精度、四档单注封顶（10万/20万/50万/100万）及精算报告与小高情报预警的物理隔离。
  2. **三模奖金优化、五流派、同义错价与时间差对冲接缝**：验证单关与串关下三种优化模式的保本配平、错价刺客流 36% 轻仓护栏、早晚场 `>= 110` 分钟对冲补单计算及同义错价精准替换。
  3. **扫地僧小高主备容灾与保密脱敏接缝**：验证主通道优先、故障秒切备通道、冷却期内备通道故障兜底重探主通道、冷却后自动回切及状态接口零模型名泄露。
  4. **四层反爬迷魂阵、子密钥分离与防重放熔断网关接缝**：验证爬虫/AI 阅读器命中静态假壳、真实浏览器与回环健康检查放行、`AES-256-GCM` + `HMAC-SHA256` 端点绑定防跨路由篡改、重放攻击触发 48 小时持久化封禁与到期自动释放。
  5. **会员授权、隐形超管 RBAC 与铁笼问答违规锁号接缝**：验证未登录握手零业务数据下发、首登激活倒计时、2 台设备限绑、5 阶密码防爆破冷却、北京时间跨零点配额重置、本地词库 0 配额秒回，以及第 5 次探底提问自动锁号并触发跨浏览器硬件指纹传染封禁新 IP。
  6. **选单工作区状态机、体彩官方对齐与安卓原生桥接接缝**：验证无 DOM 依赖的选单控制器（同场单一玩法互斥、双单关/超 8 场自动锁单关、15 场上限、玩法切换自动裁剪、31 项全比分解析、与体彩官网计算器 `0.00` 元误差对齐、`4串11` 等多串不超 100% 真实概率、五流派选队方向锚定），以及安卓 WebView UA 白名单放行与原生线性马达振幅分发。

## Out of Scope

- 真钱资金充值、线上代购出票、自动跟单下注或与任何第三方博彩交易系统对接（严格限定为内部精算分析、风控排雷与线下体彩店防错核对工具）。
- 依赖外部重型音视频静态资源的特效（全部触觉波形、微声效与粒子动画均由客户端代码实时合成）。
- Web 端自助解封 48 小时整机硬件/IP 熔断的公开或后台接口（为杜绝远程撞库绕过，48 小时熔断唯一人工干预通道为服务器 SSH 运维清理）。

## Known Quirks & Evolution Backlog（已知实现局限与待演进项）

以下行为属于 `v2.2.0` 现有代码的真实运行现状，特此立档备查，供后续版本按需单独排期优化（未立项前不得在无关改动中静默变更以免破坏既有测试基线）：

1. **实盘解析撞名混入内置演示预警 & 兜底提示文案陈旧**：
   - 服务端解析体彩官网实盘 JSON 时，若在售真实比赛的 `matchNumStr`（如 `周二002`、`周二003`、`周二007`）恰好与内置 `RAW_FALLBACK_MATCHES` 重名，会将内置演示用的硬编码 `aiAlert` 挂载到真实比赛上；同时回退内置 8 场赛事时的提示文案仍写着“周二竞彩 4 场焦点战”。
2. **双轨止损账本与个人强弱项卡片尚未持久化闭环**：
   - 「今日剩余止损护栏额度（默认 `¥300`）」与「实买单 / 模拟观察单列表」目前仅存于前端 React 内存态（页面刷新即重置为初始静态示例，额度归零后仍允许继续记入实买，且无赛果红黑结算与删除交互）；账本页的「`+19.4%` / `-62.0%` / `¥120`」强弱项统计目前为静态展示卡片。
3. **`±2` 球深盘让球线下的「一球卡盘率」近似偏差与阈值微差**：
   - 当前 `xG` 由总进球 `TTG` 加权反推而非 31 项比分泊松拟合并切分；`oneGoalProb` 直接取 `HHAD` 的 `让平 (hd)` 去水概率——在 `±1` 让球线下精确对应热门方净胜 1 球，但在 `-2 / +2` 等深盘让球线下实际代表净胜 2 球概率。此外，`microBadges` 标黄阈值为 `>= 52%`，而卡盘提示文案与卡片胶囊标黄阈值为 `>= 50%`。
4. **推演沙盒（信心滑块 / 首场腰斩）与不等倍分倍态互斥回退**：
   - 当用户已启用「三模奖金优化」或套用「五流派」不等倍方案时，一旦拉动主观胜率滑块（`!= 0%`）或开启「模拟首场腰斩」，`effectiveReport` 会静默退回按统配等倍计算的 `manualReport`，尚未在保持不等倍注数结构的前提下重算 EV 与腰斩派奖；且智能分倍态默认 `0%` 下的 `expectedValueRate` 采用 `-vigPct / 100` 近似、扩倍时未二次计入单注封顶截断损耗。
5. **早晚场时间差对冲锁利在多场长串与非胜平负玩法下的简化假设**：
   - 当前只要已选场次 `>= 2` 且最早场与最晚场 `HH:mm` 开球时间（`< 12:00` 统一视作次日 `+24h`，未跨比赛日校验）相差 `>= 110` 分钟即展示对冲方案，未严格要求 3～8 场中的中间场次也已在末场开赛前完场；且末场仅按是否勾选 `h / hh` 二分匹配 `让负 / 让胜` 对冲赔率，对末场买平局、总进球、比分或 `-2` 让球线的情形属于近似估算而非严格互补无风险套利。
6. **超管「解除锁定」操作的作用域边界**：
   - 超管点击成员行的 `🔓 解除锁定` 会恢复账号 `locked_violation` 状态并调用 `ipBruteMap.clear()` 清空全局所有来源 IP 的密码防爆破计数，但按 `ADR-0005` 规范不会清除 `security-bans.json` 中因第 5 次探底违规同步写入的 48 小时硬件指纹与 IP 熔断记录（该成员原设备仍需等待 48 小时或由管理员通过服务器 SSH 清理封禁库后方可访问）。
