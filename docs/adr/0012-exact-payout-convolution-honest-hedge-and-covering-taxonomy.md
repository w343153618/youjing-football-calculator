# 0012. 超大商集保分布派奖卷积、法定有效关数降档封顶与零诱导诚实风控契约

Date: 2026-11-20

## Status

Accepted（基于跨语言 `scipy.optimize.milp` / `Decimal` 对抗式盲审，深化并精确化 `ADR-0007` 与 `ADR-0010`）

## Context

在基于 622 场中国体彩真实完场 OOS 数据对 `v2.3.0` 精算内核与双端交互执行独立 Python 对抗式盲审时，识别出六类需要架构级固化的数学与诚实性边界：

1. **超大商集（`> 131,072` 状态）同场 `hitSet` 合并扭曲派奖尾部**：当合法复式（`<= 2,048` 注，如 8 场各选 5 项总进球打 `2串1` 共 700 注、联合状态 $6^8 = 1,679,616$）触发单场状态压缩时，将两个不同水位的命中态直接并入同一代表元 `repHitSet` 虽不改变票级线性 `EV`，却抹平了单注高赔分支，导致 `realProfitProb` 出现高达 `-5.17` 个百分点的系统性低估。
2. **赛事腰斩退算有效关数时的法定封顶档位漂移**：4 关串关中 1 场腰斩按 `1.0` 计奖时，按中国体彩规则单注封顶须随剩余 **3 关有效过关**降档至 `20 万元`，原实现按原始总腿数 4 套用 `50 万元` 档位。
3. **双场容错同场互斥单关错加与 5~8 场覆盖设计分类混淆**：双场容错在同场布置两张互斥半全场单关缓冲垫时，直接累加同场互斥派奖虚报“黑 1 场保底拿回”且遗漏半场逆转归零死角；5~8 场中不满足两两覆盖（$t \ge 2$）的独立分块串关被统称为「旋转矩阵缩水」，且子问题分配器未按条件错 1 场概率权重求解。
4. **早晚场对冲忽视体彩单关资格与负净利伪装保本**：实盘超 86% 场次胜平负/让球不开单关，原对冲器未校验末场反向池 `single === true` 即提示补单，并将凑整/抽水导致的负净利标绿称为「保本锁回」。
5. **不可信快照上限与服务端分倍上限混用**：`isValidPlanObject` 将防客户端 DoS 的 `snapshotPlan.lines <= 64` 同时施加于服务端自生成的三模奖金优化结果，致 `65 ~ 512` 注（如 `8串247`）优化后静默回退等倍。
6. **OOS 统计显著性边界与模拟账本单向统计**：622 场真实 OOS 上五池宏平均 `Log-Loss` 显著优于等比去水与单池 `Shin`（$p < 0.05$），但宏平均 `Brier` / 序数 `RPS` 的 95% 置信区间跨零且个别单池存在微幅 `Brier/ECE` 权衡；账本模拟观察单仅累加未中本金而未并列披露命中踏空单数。

## Decision

1. **超大商集保派奖分布精确积分 / 同关分桶**：对同场单一玩法复式（单场各选中项天然互斥），按单场实际派奖乘数分布执行精确多维/分步卷积或同水位无损聚类，严禁将不同水位的命中选项强行坍缩至单一代表元赔率；跨场商状态超限需归并时，仅归并派奖完全一致的等价态，或按精确美分派奖分布 DP 核算 `anyWinProb`、`realProfitProb`、`minPayout` 与 `maxPayout`。
2. **有效过关数驱动单注封顶**：凡存在腰斩/无效退算腿（`isVoidLeg`）的实票，按剔除无效腿后的**剩余有效实赛关数**查询 `statutorySingleBetCap`（若全部腿均无效则退回本金 `2 元` 不封顶误伤）。
3. **严格区分「旋转矩阵缩水」与「独立分块容错串」并修正双场保底与概率加权 CVaR**：
   - 仅当块集合严格满足任意两场子集至少被一张实票完整包含（$t \ge 2$，含 `C(5,3,2)`、`C(6,3,2)`、`C(7,3,2)`、`C(8,4,2)` 与 `C(8,6,3)` 对偶补集）时冠名「旋转矩阵缩水」；其余不相交分块或图兰局部边集统一命名为「独立分块容错串」；
   - 容错分倍求解器在内部目标与水准填充中直接引入条件错 1 场概率权重 $w_x \propto (1 - p_x) / p_x$ 及三元整数邻域精调；双场模式优先选用无死角主盘单关垫，同场多张互斥单关按单分支最小值核算保底并显式披露半全场逆转归零死角及整单真实归零率 `1 - winProb`。
4. **早晚场对冲法定单关硬门禁与盈亏双轨定性**：`resolveComplementaryLateHedge` 强制要求末场反向候选所在奖池 `single === true`；仅当 `lockedNetProfit > 0` 时定性为「时间差对冲锁利」（绿字），`= 0` 定性为「零损锁回本金」，`< 0` 定性为橙色预警「早场红单减损补单」（严禁称锁利或保本）。
5. **读写分离的分倍条数安全上界**：客户端传入的不可信 `archetype` 快照继续严守 `snapshotPlan.lines <= 64`（遵循 `CODING_STANDARDS.md` 防 DoS 边界）；服务端内部由 `optimizeBonusPlan` 生成的 `bonus` 分倍方案放宽至 `<= 512` 条实票，前端对 `> 512` 注复式置灰三模优化入口并给出明确说明。
6. **全链路统计与风控诚实披露**：槽位①补充含单关双场的 `单关 + 2串1` 零假中奖组合择优并区分纯退本金（`netProfit === 0`）与净赚；槽位②单矛+单盾按同成本精确整数对数财富效用寻优；拖油瓶体检统一对比 `realProfitProb` 且禁止将双场非单关串关砍成不可出票单场；同义双选替换自动挂载反比例配平且不破坏单关资格；主观胜率滑块对称收敛为 `[-15%, +15%]`；账本并列透出 `paperWonCount` 与 `paperLostCount`。
