# 0018. 体彩历史参考单写者 WAL 底座、双维走势与客观事实隔离架构

Date: 2026-11-23

## Status

Accepted（演进并补充 `ADR-0002`、`ADR-0009`、`ADR-0010`、`ADR-0011` 与 `ADR-0016`）

## Context

五轮双模型真实体彩数据实测与清醒态复核揭示出现网历史参考链路、走势表达与排雷协同中的四项工程边界问题：

1. **上游赛果截断、残页落盘与启动首报缺失**：现网赛果拉取硬限前 3 页且中途分页报错后仍将残缺页写入缓存；在售启动时刻已有显著比例玩法池偏离官方归档首报，且历史接口存在比分池 `s-1sh/d/a` 别名、赛后统计 `wbsjStats` 未来信息穿越风险及官方空板/超时回退被误记为逐池停售的问题。
2. **单跳水位箭头假升真降误导**：中国体彩整池同步调整返还率时，单项水位与该项去水真实隐含概率可以同向变化；现网单凭末跳 `trend === -1` 定性 `"真防冷急降"` 易误导选号。
3. **排雷情报主观消化度推断与三处接缝缺陷**：扫地僧小高在无核验外部消息时仍默认输出“水位已部分消化市场热度”，且存在未开售玩法虚构 `12.0%` 抽水、有效数值 `0` 被 `|| 45` 覆盖、串关告警按 `"周六001"` 等重名展示编号或数组位置盲配导致跨日串台及变盘后残留旧结论的风险。
4. **在线重算样本稀缺与近并列浮点敏感**：770 场归档与 622 场实盘验证自然 `HAD-only` 持续缺池超 60 秒为 `0` 场（积累 800 场同域样本至少需 `14.5 年+`）；同时改变 8 场冷求解浮点累加顺序会在近并列压力用例中扰动内部候选整数倍数。

## Decision

1. **显式所有者 `collectorWorker` 单写者 `node:sqlite` WAL 与主线程不可变快照交换**：
   - 仅在显式声明采集所有权的服务入口（生产常驻进程、开发服务器生命周期或指定采集测试/运维命令）拉起唯一后台 `collectorWorker` 独占 `node:sqlite` WAL 写连接（宿主不支持时自动降级追加式 `JSONL`），`vite build` 与常规并发单测保持零后台线程副作用，并由统一运行时 `dispose` 显式停轮询、刷游标、关库退线程。
   - HTTP 主线程对历史链路保持零磁盘/网络 I/O，仅在校验序号、版本与校验和后原子替换进程私有不可变快照；对接体彩公开四接口执行冷启动四级回补（实时自适应单飞轮询、24 个月赛果 `<= 60` 天分窗全页核齐提交、在售与新上架异步补归档首报、近 90～120 天详情优先回补），强制归一 `s-1sh/d/a → s1sh/d/a`、拒收 `wbsjStats`、执行 `matchDate + 3 天` 缺公告时间禁运、记录双时钟并防异步回填倒盖；空板/超时/维护/旧缓存回退记录为板级状态并在前台显式标出「上次有效报价」采集时刻；沿用 18 个月热库、24 个月赛果索引与至少 36 个月冷档 `.jsonl.gz`（解压逐行核验后再清热库），与用户个人双轨账本物理分离。
2. **双维盘面走势分层呈现**：按 `(matchId, poolCode, goalLine, optionKey)` 对齐（让球线变动自动分段），在同有效选项集与统一去水口径下实算「首报→当前」真实隐含概率净变化百分点（缺归档首报标 `自本系统首次观测`，不足两帧不判趋势）与「上一报→当前」水位/时间/方向；窄屏首屏按钮保持外简紧凑防挤压，全玩法与底牌抽屉完整并列双维事实，废除 `"真防冷急降"` 单跳定性与水位简单反转替代。
3. **扫地僧小高纯客观事实增强与严格 `matchId` 版本绑定（演进 `ADR-0002` & `ADR-0011`）**：单场点诊与多场串关会诊统一传递同 `sportteryTeamId` 已观测休息间隔上界、近 90 天最多 12 场（满 8 场作同期预期对照，早盘回放仅用当时可见报价）客观战绩账本及消息-变价时序并列陈述（严禁推断消化比例或改动精算概率/配单权重，无核验消息统一标 `无可核验信息`）；修复缺池假抽水与零值覆盖；彻底废除按展示编号/标题子串/下标位置匹配，会话告警与缓存严格绑定唯一 `matchId`、开售池掩码、让球线、报价版本签名与 `30 分钟` 有效期，变盘或过期立即自动撤回。
4. **精算内核 100% 出厂冻结与隐形总控台只读监测**：撤下在线重算 Worker、800 场晋级任务与自动熔断器，生产预测、`3+1` 配单、`1.01` 错价红线、法定算奖与封包格式 100% 保持出厂冻结，以冻结输入回放锁死四槽、票列、倍数与算奖等价性；后台只读记录自然缺池观测、真实工作台请求暴露、准入/拒单与四回报桶校准评分，连同热库/WAL/冷档实际占用与采集进度统一经隐形总控台加密只读页签向超级管理员展示；8 场冷求解与大包提速独立剥离为后续专项课题。

## Consequences

- **正面收益**：主线程请求保持零历史磁盘/网络阻塞且单测/构建干净无锁冲突；彻底消除分页残页污染、单跳水位箭头假防冷误导、主观消化度臆断及同名赛事编号串台；精算生产公式零漂移风险。
- **被拒备选**：拒绝在 HTTP 主线程直接同步读写 SQLite；拒绝用反转末跳水位箭头代替去水概率重算；拒绝保留无外部消息时的默认“已部分消化热度”话术；拒绝在稀有缺池样本远未达统计功效时启用线上自动改参；拒绝在本期混入改变浮点累加顺序的冷求解裁剪。
