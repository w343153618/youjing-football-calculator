# 0011. 采用「1-2-3 向导动线 + 按步单主按钮底栏 + 只读精算上下文驱动双维协同会诊」架构

Status: accepted

早期工作台在手机端四页签统一悬挂手动串关悬浮条、在电脑端按「左选球 → 中审单 → 右配单」逆序排布三栏，且「扫地僧小高」多场联合会诊未感知用户是否已套用 `3+1 精算配单` 或三模奖金优化，导致移动端配单页出现双底栏重叠打架、电脑端视线来回折返，以及用户刚用精算配平注单就被小高按散户裸串批评的体验割裂。

我们决定：

1. **双端收敛至「① 赛事雷达选球 → ② 精算配单 → ③ 审单锁利」线性动线与按步单主按钮（Primary CTA）**：电脑端三栏调整为从左至右顺次排布（左栏选球、中栏精算配单、右栏五维审单锁利与情报账本切换）；移动端在「精算配单」与「情报账本」收起手动串关悬浮条（演进更新 `Spec 0005` 四页强挂底栏约束），使每个阶段底部仅保留唯一无遮挡核心动作，并在已选球时默认实时开启雷达选队同步锚定。
2. **严守 `ADR-0002` 单向只读边界下的双维协同会诊**：服务端在组装联合会诊上下文时，将权威精算引擎算出的方案来源（如稳健保本、期望效用、容错缩水、三模分倍或未优化手动等倍串关）、假中奖清零状态、防卡盘双选与旋转矩阵回血底线以**只读结构事实**注入小高会诊上下文，输出「🛡️ 已构筑的精算防线 + ⚡ 盘面消化度与残余实战暗雷」双维报告；小高输出绝不反向修改五池闭合概率或实票分倍数学内核。
