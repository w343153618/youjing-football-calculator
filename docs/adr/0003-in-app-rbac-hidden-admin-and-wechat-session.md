# 采用内嵌式 RBAC 隐形超管总控台（2b）与微信级长期免登断网保护架构

为避免单独部署一套外部管理后台带来的双域名维护负担与暴露面，同时避免在普通成员界面展示任何“管理员入口”诱发好奇试探，我们采用应用内基于角色权限（RBAC）渲染的隐形总控台方案（2b）：普通成员登录后界面与网络响应不含任何管理菜单痕迹，唯独超级管理员账号登录后自动浮现「👑 总控台」管理全部成员的首次激活计时、设备限绑（默认 2 台）、每日智能额度与违规日志。登录态采用 365 天长效令牌配合阶梯式防爆破冷却（连续输错 5 次起按 1m/5m/15m/1h/24h 递增锁定），并在客户端实施离线缓存韧性保护——短暂断网或网络切换绝不踢用户下线，恢复联网后自动静默续接原会话。

## 演进（2026-11-26）：两级管理权限分离（`superadmin` vs `subadmin` 分权子管理员）

为支持核心协管成员独立给名下客户开号，同时从架构层面彻底杜绝协管修改、停用或删除超级管理员（`superadmin`）及跨归属操作他人账号的风险，我们在原有 `superadmin | member` 二元角色基础上引入受限的 **`subadmin`（分权子管理员）** 角色，并确立以下不可越权边界：

1. **创建人归属隔离（`createdBy`）**：每次开号持久化记录创建者标识；`subadmin` 在前端总控台与服务端接口均仅可见自身账号与名下创建的 `member` 账号，`superadmin` 及非本人创建的账号对其完全不可见。
2. **硬性角色与操作封顶**：服务端在账号管理核心引擎与加密网关双层校验操作者身份——`subadmin` 绝对禁止查看、修改、重置密码、停用或删除任何 `superadmin` 或非本人创建的账号；对自身仅开放「修改自身密码」与「解绑自身设备」，禁止自提配额；对名下新开或管理的普通成员强制封顶单号设备上限 `<= 5` 台、每日智能额度 `<= 100` 次，且仅能创建 `member`（禁止套娃发展下级子管理员）。
3. **监控面板与总控权限保留**：总控台中的「🛡️ 风控与违规提问日志」与「📊 历史库与校准监测」及对应服务端监控载荷仅限 `superadmin` 访问；`superadmin` 保留全员账号全景视图（含开号归属展示）及一键升降 `subadmin` 权限的最高控制权。
